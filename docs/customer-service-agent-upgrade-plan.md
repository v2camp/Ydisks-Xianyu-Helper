# 客服 Agent 升级计划

> 版本：1.0
> 日期：2026-09-20
> 状态：已实施并部署（v1.0.14-local-20260921）
> 关联代码：`internal/engine/aimatch`、`internal/engine/ai_scope.go`、`internal/engine/ai.go`、设置页「AI 客服配置」编辑区

## 一、背景与问题

系统自带的 AI 自动回复只接管「砍价意图」的消息，其余消息走关键词/默认回复。

- 接管逻辑写死在 `internal/engine/ai_intent.go`：意图正则与接管策略都在代码里，改动要发版。
- 只有砍价消息触发 AI，买家常问的资源内容、发货方式、库存/在售、政策类问题都被旧机制处理，体验生硬。
- 负向词表（退款/退货/投诉等）偏窄，IM 里实际出现过的「违规、扣分、封号、申诉」等说法拦不住。

**需求**：AI 客服的边界、策略、语料都要能低代码配置（改配置即时生效，不写代码、不重启），并把 AI 的接管范围从「仅砍价」扩展为与店铺业务匹配的合理范围。

## 二、目标与范围

1. 统一判定语言：用「组合词」布尔表达式替代硬编码正则，一处语法三处复用。
2. 三层可配置：边界（哪些意图交给 AI）、语料（FAQ 与在售清单）、策略（报价话术）。
3. 向后兼容：未配置或配置非法时回落内置行为（仅砍价接管），历史行为不变。
4. 有据可答：FAQ 命中的店规与在售清单注入 AI 提示词，回答以店铺知识为依据。

不包含（后续另行规划）：语义向量检索、槽位抽取与多轮流程、投诉/纠纷自动处理。

## 三、整体设计

### 3.1 组合词语法（aimatch 包）

表达式由词与运算符组成，低代码友好：

| 符号 | 含义 | 示例 |
|---|---|---|
| `\|` | 或 | `(便宜 \| 优惠)` |
| `&` | 且 | `(砍价 & 元)` |
| 相邻词 | 默认「且」 | `百度网盘 发货` |
| `!` | 非 | `夸克 & !会员` |
| `( )` | 分组 | `(砍价 \| 优惠) & (元 \| 块)` |
| `"..."` | 正则词 | `"第[一二三0-9]季"`（用于变动的数字） |

- 普通词按「包含」匹配，忽略大小写；括号、竖线等符号不用转义。
- 正则词必须用双引号包裹，内部 `(` `|` 不作为语法符号。
- 空表达式恒不命中；语法/正则非法时返回错误，配置侧按「忽略该项或整体回落」处理。

### 3.2 三层配置（存于系统设置 system_settings）

| 配置键 | 层 | 内容 |
|---|---|---|
| `ai_scope_config` | 边界 | `intents`（意图白名单：id/enabled/ai/match）+ `negative`（负向组合词） |
| `ai_knowledge_config` | 语料 | `faq`（问答知识）+ `catalog`（在售清单） |
| `ai_policy_config` | 策略 | `min_price_reply`（最低价话术，`{amount}` 占位）+ `no_discount_reply`（拒绝话术） |

判定顺序（消息进来后）：

1. 负向组合词命中（含内置词表 ∪ 配置 negative ∪ 扩展词表 `ai_complaint_keywords`）→ 一票否决，交给默认回复/人工。
2. 依次匹配启用的意图：`enabled=false` 忽略；`ai=false` 只记录命中（写入对话历史标签）不接管。
3. 任一 `ai=true` 的意图命中 → AI 接管；否则走默认回复。
4. 接管后：命中 FAQ 的答案与在售清单注入 system prompt；报价超出边界时套用策略话术。

配置读取规则：每次回复从 settings 读取（与既有 ai_api_key 读取方式一致），改配置即时生效，无需重启。JSON 非法、意图词表非法或无可用意图时回落内置。

### 3.3 内置默认（未配置时）

等价于历史行为：仅 `bargain` 意图可接管；负向词为内置投诉词表；询价/订单/咨询意图仅参与命中标注（保证「多意图归并 ambiguous」等历史语义不变）。

## 五、IM 梳理与接管范围依据

对账号 11873716 的 430 条入站消息 / 56 个会话做分类梳理，买家常问问题与 AI 适用范围如下：

| 类型 | 代表话术（摘录） | 是否交给 AI |
|---|---|---|
| 砍价/议价 | 「能便宜点吗」「130块我就都要了」 | 是（原有） |
| 资源/商品内容 | 「是正版的吗」「有音频嘛」「文字版在哪里」 | 是（新增 product_qa） |
| 发货/网盘兼容 | 「百度网盘发货吗」「有夸克的吗」「资源码怎么用」 | 是（新增 delivery） |
| 库存/在售 | 「有第三季了吗」「可以单买第二季吗」「全集吗」 | 是（新增 stock，依据在售清单） |
| 售后/退款/纠纷 | 「那我退了吧」「我要退款」 | 否（负向拦截） |
| 账号风控敏感 | 「被举报了」「扣了20」「不能挂永久」 | 否（负向拦截，绝不 AI） |
| 商务/广告/合作 | 网盘拉新推广、货源对接 | 否（人工） |
| 闲聊 | 「在吗」「谢谢」 | 否（维持默认回复） |

## 十一、评测驱动优化记录（2026-09-21）

决策层评测集 v1 与内容层评测落地后，对升级计划第五节真实话术做了复现核对，结论如下：

1. **数字报价匹配非缺陷（澄清）**：内置砍价组合词 `builtinBargainExpr` 中的 `\\d` 位于普通 Go 字符串内，编译后即为 `\d`，转义正确；实测「20块卖吗」「30元可以吗」均正常命中。此前疑似「双反斜杠导致不匹配」为误报，无需改动。
2. **真实口语负向漏拦（已修复）**：真实话术「那我退了吧」「扣了20」不含连续子串「退款」「扣分」，现有负向词表（内置 + 生产种子配置）均拦不住。评测集新增 `aiEvalSpecialRealPhrase` 标注锁定这两条用例，并将生产种子配置负向词表追加 `退了|扣了`。**生产库 `ai_scope_config` 的 negative 需同步追加 `退了|扣了` 后才对线上生效**；本机评测集仅代表期望基线。

## 十二、优先级优化计划（2026-11-01）

> **本节不维护状态。** 项号（A/B/C/D）、四态状态与判定依据只由 `docs/SDD.md` 维护，本节只说明每项为什么存在、落在架构哪里、拿什么验收。
> 排序尺度固定为 **准确性 > 通用性 > 热点 > 性能**，同档内按「是否卡住其它项」排序。

### 12.1 P0 准确性

| 编号 | 事项 | 架构落点 | 前置 | 验收信号（可机检） |
|---|---|---|---|---|
| A1 | 评测口径修正 | `internal/evalharness`、`cmd/evalexport`、`cmd/evalreplay` | 无 | 逐条展开样本数 60→70；可机检期望 9 条；判定失败计入分母 |
| A2 | 发货渠道事实化：卡密正文 → `card-channel` | `internal/engine/ai_live_context.go` + `internal/netpan` 卡密解析 | A3 | `grounding_source=card-channel` 占发货类会话 ≥60% |
| A3 | FAQ 通用话术降权（「以商品详情页说明为准」） | `system_settings.ai_knowledge_config`（配置即时生效） | 无 | 配置版本号变更；不再出现在发货类回复中 |

（全部是「以商品详情为准 / 我这边也说不准」这类回避话术）。其余各项都不影响这 9 条。

## 十三、周度定时任务与计划的协同

### 13.1 现状问题（三次运行的共同失效）

| 问题 | 证据 | 后果 |
|---|---|---|
| 取不到当周数据 | 连续三周生产库不可直连、仓库零新导出 | 周报只能在旧快照上推演，结论重复 |
| 只写分析不验收 | 三次周报均以「输出改进思路」结束 | 计划项状态从不推进，「在树」被误读为「已修好」 |
| 报告与计划两份文档 | 周报独立成篇，计划文档不记录状态 | 同一问题在四周里被重新发现三次 |

### 13.2 改造后的任务职责

**从「分析周报生成器」改为「状态看板推进器」**：每周只做三件事——核验上周计划项走到哪一格、把新证据补进对应格子、只对「未落地」和「新出现」的项重排优先级。

### 13.3 任务步骤（固定六步）

1. **数据可得性自检**：能否连生产库、仓库是否有新导出。取不到就当节写明降级，不再用旧快照推演当周问题。
2. **离线跑评测规则层**：`go run ./cmd/evalreplay -dry-run -per-message`。该命令不调用模型、不连库，纯粹用样本快照验规则层，可随时跑；9 条可机检期望是最稳的回归线。
3. **逐项核验计划状态**：对 §12 的每一项，按 12.1 的四态判定，给出「状态 + 判定依据（提交号 / 配置键 / 指标值）」。
4. **归因分布**（有数据时）：`answer_source` 与 `grounding_source` 分布，重点是 `card-channel` 占比。
5. **只对未落地项排序**：严格按 准确性 > 通用性 > 热点 > 性能。
6. **回写**：更新 `docs/SDD.md` 的状态列与判定依据（唯一真相源），本文件 §12 不含状态、不必改（不新建文档）。

### 13.4 频率

保持每周一次（周六 18:30）。数据以周为粒度，且当前瓶颈是「发布核验」而不是「发现新问题」——日报只会重复同一批结论，反而稀释信号。
若 B4（样本导出）落地，可把频率提到每周两次，因为那时每周都有新样本可测。
