# 客服 Agent 评测机制方案

> 版本：1.0
> 日期：2026-09-21
> 状态：方案讨论稿
> 关联：`docs/customer-service-agent-upgrade-plan.md`（Agent 升级计划）、`docs/test-separation-plan.md`（测试分离方案）、`docs/dev-test-environment-plan.md`（本机环境治理）

## 一、背景与目标

客服 Agent 已有清晰策略（三层可配置：边界 `ai_scope_config`、语料 `ai_knowledge_config`、策略 `ai_policy_config`，组合词由 `aimatch` 解析）。需要配套评测机制：

- **用户卡口门禁**：配置变更（边界/语料/策略）合入前自动评测，防止写坏接管行为。
- **Agent 指标优化**：用评测数据驱动三层配置调优。

评测机制建立在测试分离方案之上，且**决策层评测可做到零账号**。

## 二、评测分层

评测分两层，分开对待：

### 1. 决策层评测（确定性，零账号）

测「这条消息该不该 AI 接管、进哪个意图、是否被负向词拦截」：

| 指标 | 含义 | 对应规则 |
|---|---|---|
| 接管准确率 | 该 AI 接管的接管、不该的拒绝 | 意图白名单 + 负向词 |
| 负向拦截率 | 退款/投诉/封号类绝不进 AI | 负向组合词 |
| 意图分类正确率 | 砍价/商品/发货/库存归类准确 | aimatch 组合词 |
| 误伤率 | 该默认回复的被抢走 | 边界配置 |
| 特殊语义保持率 | 多意图归并 ambiguous、`ai=false` 只标注不接管、负向扩展词表 `ai_complaint_keywords` 行为不变 | 升级计划既有语义回归 |

这层用「消息 + 期望判定」标注集离线跑，完全零账号、确定性、可进门禁。**这就是用户卡口门禁**。特殊语义保持率单独成指标，防止后续调优破坏升级计划已声明的历史行为。

### 2. 内容层评测（需要 LLM，可 mock 可真实）

测「接管后回复质量」：

| 指标 | 含义 | 评测方式 |
|---|---|---|
| FAQ 命中率 | 回复是否命中知识库答案 | mock 模型确定性断言 |
| 在售清单引用率 | 涉及库存/在售时是否引用清单 | mock 模型确定性断言 |
| 策略话术覆盖率 | 报价超出边界时是否套用 min_price/no_discount | mock 模型确定性断言 |
| 回复质量分 | 真实模型输出质量 | 真实模型 + 人工/评分集 |

- **回归**用 mock OpenAI server（现有 `ai_test.go`、`ai_scope_test.go` 模式），断言确定性行为。
- **优化**用真实模型跑评测集出质量分，判定方式建议 LLM-as-judge 或人工抽样，驱动 FAQ/策略话术调优。

## 三、评测集来源（承接脱敏快照）

- **离线标注集（决策层）**：以 Agent 升级计划第五节 430 条真实 IM 消息 / 56 会话分类为基础扩充，标注「期望意图 + 是否接管 + 期望负向拦截」→ 入库为评测集。
- **回放样本（内容层）**：测试分离方案的脱敏快照中的真实 IM 会话 → 离线重放给 Agent 决策链，观察接管后回复。
- 全部脱敏后入库，零账号运行。

## 四、卡口门禁（用户卡口）

- 决策层评测进默认门禁：任何 `ai_scope_config` / `ai_knowledge_config` / `ai_policy_config` 变更必须通过评测集。
- 形式：`TestAIReplyScopeKnowledgeIntegration` 扩展为数据驱动评测集 + 配置合法性校验。
- 目的：防止配置写坏接管行为（负向词漏拦、意图错收、误伤默认回复）。

## 五、指标优化闭环

- 决策层：评测集跑分 → 调整组合词/负向词/意图白名单 → 复跑评测集。
- 内容层：mock 保证回归；真实模型出质量分 → 优化 FAQ/策略话术 → 复测。
- 闭环链路：主号脱敏快照 → 评测集 → 决策层门禁 + 内容层优化 → 反哺 Agent 配置。

## 六、落地顺序建议

1. 建立评测集 v1（从 430 条真实消息分类扩充标注）。
2. 决策层评测 runner（数据驱动，输出四类指标），接入门禁。
3. 内容层评测：mock 模型确定性断言 + 真实模型质量分脚本。
4. 与测试分离方案的回放样本衔接，持续扩充评测集。
